# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build and Run Commands

- The "source of truth" language here is MoonScript. Lua files are automatically compiled and run directly by moonrun and/or moonbuild (which are both available on PATH and also in this directory for your reference). You should only need to deal directly with MoonScript files.
- Running MoonScript: `moonrun path/to/module.moon` (or use a hashbang and make it executable)
- Run tests: `moonrun path/to/module.moon --test` (or, if executable, `path/to/module.moon --test`) Every library file should contain unit tests (also inside the same file) that are accessible in this way. You can use bignum.moon as an example.

## Code Style Guidelines

- **Languages**: Lua and MoonScript (.lua and .moon files), although you should only be editing MoonScript files.
- **Formatting**: ALWAYS use tabs; just be aware that autogenerated Lua files get spaces, however
- **Types**:
  - Check types explicitly (e.g., `type(value) == "string"`)
  - Include error messages for type mismatches
- **Naming**:
  - Use snake_case for variables and functions
  - Use PascalCase for classes
- **Error Handling**: Use explicit error() calls with descriptive messages
- **Syntax**: Both Lua and MoonScript syntaxes are used; new files should be written in MoonScript and match existing formats
- **Dependencies**: All external dependencies should be required at the top of the file (except for test mode, where additional files may be required at runtime)
- **Testing**: Test cases are included in the same file, triggered by the `--test` flag
- **Test Tooling**: There is an assertion factory available in `cli_utils.moon` that will help you write tests. Remember to always exit code with the number of fails, if the test is run with the `--test` flag.

## Very important: ALWAYS USE TDD

- Decide what you want to build first; one feature at a time.
- Write a test for it that you expect to fail first
- RUN THE TEST AND WATCH IT FAIL. This verifies that the test is valid.
- Add the code to make the most recent test pass.
- Repeat until feature-complete.
- Refactor to improve code quality.
